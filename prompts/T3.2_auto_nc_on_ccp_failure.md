## Context

HACCP 시스템의 본질은 "CCP를 벗어난 사건이 즉시 추적·시정·검증되어야 한다"는 것입니다. 종이로 운영하면 시정조치 누락이 일상이지만, 시스템화하면 **자동으로 Non Conformance(NC) 레코드가 발생**하고 책임자에게 알림이 가도록 만들 수 있습니다.

지금 우리는:
- T2.3에서 Job Card 측정값 → Quality Inspection 자동 생성을 만들었음

- `Non Conformance` DocType은 ERPNext 표준에 존재하지만 필드가 부족 → fixtures에서 Custom Field로 보강 완료

이제 CCP 이탈을 감지해서 자동으로 NC를 만드는 마지막 연결고리를 만듭니다.

## Task

### 1) Server Script: CCP 이탈 감지 및 NC 생성

위치: `food_mes_kr/food_mes_kr/server_scripts/quality_inspection_hook.py`

주요 함수:
```python
def auto_create_non_conformance_on_ccp_failure(doc, method=None):
    """
    Quality Inspection on_submit hook.
    CCP 항목 중 status='Rejected' 인 readings가 있으면 NC를 자동 생성.
    """
```

동작:
- QI의 `readings` 순회
- 각 reading의 specification(Quality Inspection Parameter)에 대해, 부모 Item의 Item Quality Inspection Parameter에서 `is_ccp=1` 여부 확인
- CCP이면서 `status="Rejected"` 인 reading이 있다면:
  - 새 `Non Conformance` 생성
  - 다음 정보 채움:
    - `subject`: `[CCP-FAIL] {item_code} - {parameter}` 형식
    - `details`: 자동 생성된 상세 (측정값, 한계값, 측정 시각, 측정자)
    - `severity`: 자동 분류 — 측정값이 한계 ±10% 안이면 "Medium", 이상이면 "High", 미생물 CCP면 무조건 "Critical"
    - `linked_quality_inspection`: 이 QI 링크
    - `linked_batch`: QI의 batch_no
    - `assigned_to`: Quality Manager role 보유자 첫 번째
    - `due_date`: today + 3일
    - `process_owner`: Production Supervisor role 보유자
- 생성된 NC를 Quality Inspection의 별도 메모 필드에 기록 (역참조)
- 이메일 알림 발송 (Quality Manager 전원 + Production Supervisor)

## Constraints

- **이메일 발송은 큐로**: 동기 발송하면 QI submit이 느려지고 메일 서버 장애 시 submit 자체가 실패. `frappe.sendmail(now=False)` 사용.
- **NC 생성 실패가 QI submit을 막아서는 안 됨**: try/except로 감싸고 실패 시 Error Log에 기록만. CCP 데이터는 어떻게든 살아남아야 함.
- **"Critical" severity 자동 판정 룰은 명시적으로**: Quality Inspection Parameter의 parameter_group이 "Microbiology" 이거나 항목명에 "균", "Pathogen", "E.coli", "Salmonella" 포함 시.
- **법적 효력**: NC 자동 생성은 보조 수단이고, **수동 NC 생성도 항상 가능**해야 함. 자동 생성 NC를 사후에 사람이 편집 가능하게 권한 부여.
- 한국어 이메일 본문은 `frappe._()` 처리 + 한국어 lang 파일 등록.

## Acceptance Criteria

1. CCP 항목이 NG로 QI submit → NC 자동 생성 (List에서 확인)
2. 생성된 NC의 모든 자동 필드 정확히 채워짐
3. Quality Manager에게 이메일 발송 (Email Queue에서 확인)
4. CCP 아닌 항목 NG → NC 생성 안 됨
5. 같은 QI amend → NC 중복 생성 안 됨
6. 미생물 CCP 항목 NG → severity가 Critical
7. 자동 생성된 NC를 사람이 수정 가능 (권한 정상)
8. NC 생성 실패해도 QI submit 자체는 성공 (Error Log에 기록)
9. 5개 단위 테스트 모두 통과
